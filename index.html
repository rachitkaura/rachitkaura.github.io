Product scope and decisions

Defined separate candidate and employer journeys across discovery, work preferences, screening and application tracking. Made candidate publication opt-in and kept the fictional sample workspace separate from live records, so the product can be explored without publishing a real profile.

Technical delivery

Built and connected the React/TypeScript interface, API routes, Cloudflare Workers, D1/SQLite database and private R2 file storage. The pilot uses versioned schema migrations, server-side ownership checks and interview-slot conflict protection across the hiring workflow.

Recruiting and candidate experience

Employers manage screening questions, shortlists, team notes, application stages and interview availability. Candidates control profile visibility and contact sharing. Live messages and booking require mutual interest; downloadable interview calendar files include a 15-minute reminder.

Trust and validation

Job posting requires two checks: company-domain proof and admin approval. Profile photos use manual ID review with private image access. Four automated suites exercise API isolation, career tools, live hiring and verification using synthetic identities, image fixtures and SQLite migrations.

Current stage: a working pilot in active development. Plus career tools use rules and templates for editable documents and guided practice. Scheduling includes downloadable calendar events.

02 · APPLIED AI

Multi-agent personal AI system

PERSONAL PROJECT · PUBLIC SPECS

I designed and deployed a multi-agent AI system with an orchestrator and three specialist agents, implementing task routing, scoped tool access and traceable decisions, tool calls and outputs. The project also includes a 30-case evaluation harness covering task completion, routing accuracy and failure modes.

Architecture and boundaries

Requests enter through the orchestrator. Each specialist has a Markdown specification defining its scope, tools, authority and escalation rules. Cross-domain work returns through the orchestrator rather than relying on direct agent-to-agent coordination.

What changed through iteration

Vague boundaries led to overlapping answers, while free-form hand-offs lost context. I tightened the refusal criteria and introduced a standard hand-off brief to preserve constraints and open questions.

Evaluation

I built a 30-case harness to evaluate task completion, routing accuracy and failure modes, using the results as a release gate and documenting the architecture and known limitations. The linked public repository shares the sanitized agent specifications and design decisions.
